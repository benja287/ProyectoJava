IMPORTANTE — DÓNDE SE GUARDAN LOS DATOS
---------------------------------------
  • Metadatos (usuarios, trabajos, pagos, actividades…): MySQL jyaa2026_bd1
  • Archivos PDF (trabajos) y comprobantes de pago: tabla archivos en MySQL (BLOB)
    En trabajos/pagos solo se guarda documentoUrl / comprobanteUrl (/api/archivos/{id})
  • Hibernate crea/actualiza la tabla archivos al deploy (hbm2ddl.auto=update)

  Ejemplo en tabla trabajos:
    documento_url = /api/archivos/8

  El binario está en tabla archivos (id=8, columna contenido LONGBLOB).
  phpMyAdmin: SELECT id, nombre_original, tipo, LENGTH(contenido) FROM archivos;

  Si al subir PDF aparece "Data too long for column contenido" (error 500), la columna
  quedó como BLOB chico (64 KB). Ejecutar UNA VEZ en phpMyAdmin:
    ALTER TABLE archivos MODIFY contenido LONGBLOB NOT NULL;
  Luego redeploy o reiniciar Tomcat y volver a subir el archivo.


1. REQUISITOS
-------------
  • JDK 21, Maven 3.8+, Tomcat 10.1+ (local opcional)
  • Push a GitLab rama main → pipeline despliega Docker + Tomcat
  • MySQL: jyaa2026_bd1 en mysql.java.linti.unlp.edu.ar:3306


2. STACK ENTREGA 4
------------------
  • JAX-RS: Jersey 3.1.9
  • CDI: Weld 6.0.4 (beans.xml + @RequestScoped)
  • JSON: Jackson (jersey-media-json-jackson)
  • OpenAPI/Swagger: swagger-jaxrs2-jakarta + Swagger UI en /swagger-ui/
  • Persistencia: misma capa DAO/JPA de entrega 3


3. COMPILAR LOCAL (opcional)
----------------------------

  mvn clean package
  → target/jyaa2026-grupo1.war

  Esperar pipeline verde. URL:

5. PROBAR CON SWAGGER UI (resumen — detalle en GUIA-PRUEBAS-SWAGGER-ENTREGA4.txt)
--------------------------------------------------------------------------------
  1) Abrir:
       https://grupo1.jyaa-ci.linti.unlp.edu.ar/swagger-ui/index.html

  2) Verificar health:
       GET /api/health  →  "jpa": true

  3) Flujo participante + autor:
       POST /api/registro  (nombre, apellido, email, password)
       POST /api/login
       POST /api/trabajos  (titulo, resumen, tipo, autorId…)
       POST /api/trabajos/{id}/documento  (multipart, archivo PDF)
       PUT  /api/trabajos/{id}/enviar

  4) Flujo admin usuarios:
       GET  /api/usuarios
       PUT  /api/usuarios/{id}/roles
       PUT  /api/usuarios/{id}/activo

  5) Flujo admin pagos:
       POST /api/pagos  (usuarioId, monto, metodo, requiereFactura…)
       GET  /api/pagos/pendientes
       PUT  /api/pagos/{id}/validacion  (aprobar/rechazar + motivo)

  6) Flujo admin actividades:
       POST /api/actividades  (titulo, sala, inicio, fin, tipoActividad)
       (intentar otra en mismo aula/horario → 400 conflicto)

  7) Flujo OC:
       PUT  /api/usuarios/{id}/promover-evaluador
       POST /api/asignaciones-evaluacion  (trabajoId, evaluadorId)
       DELETE /api/asignaciones-evaluacion/{id}

  8) Flujo evaluador:
       PUT  /api/asignaciones-evaluacion/{id}/respuesta  (aceptar: true/false)

  9) Flujo participante — pago:
       POST /api/pagos  (usuarioId, monto, metodo: EFECTIVO|TRANSFERENCIA|TARJETA, requiereFactura)
       POST /api/pagos/{id}/comprobante  (multipart, archivo comprobante)
       GET  /api/pagos/usuario/{usuarioId}/estado  (Pendiente/Aprobado/Rechazado)

  10) Flujo cronograma personal:
       POST /api/cronograma/{usuarioId}/actividades/{actividadId}
       GET  /api/cronograma/{usuarioId}
       DELETE /api/cronograma/{usuarioId}/actividades/{actividadId}


6. VERIFICAR PERSISTENCIA EN MySQL (phpMyAdmin)
-----------------------------------------------
  https://dbadmin.jyaa-ci.linti.unlp.edu.ar/  → base jyaa2026_bd1

  Tras POST /api/trabajos:
    SELECT id, titulo, documento_url, estado FROM trabajos ORDER BY id DESC LIMIT 5;

  Tras POST /api/pagos:
    SELECT id, monto, estado, comprobante_url FROM pagos ORDER BY id DESC LIMIT 5;

  documento_url apunta a /api/archivos/{id}; los bytes están en tabla archivos.

8. ALCANCE GRUPO DE 3 INTEGRANTES (PDF cuarta entrega)
------------------------------------------------------
  Implementado en backend/:
  • Admin: ABML usuarios, roles, activar/desactivar
  • Admin: validar pagos pendientes (aprobar/rechazar, motivo, ajuste monto)
  • Admin: ABML actividades + validación conflictos sala/horario
  • OC: asignar/desasignar evaluadores, promover evaluador
  • Evaluador: aceptar/rechazar asignación
  • Autor: crear/enviar trabajos + adjuntar documento PDF
  • Participante: registro + crear trabajos (rol Autor automático)
  • Cronograma personal: agregar/quitar/visualizar + validación superposición
  • Pagos: registrar comprobante + consultar estado
