Clases y objetos de dominio

Usuario

  • Atributos: id (UUID), nombre, apellido, email, activo, roles (Set&lt;Rol&gt;).
  • Métodos: constructor, getters (getId, getNombre, getApellido, getEmail, isActivo, getRoles), desactivar(), activar(), agregarRol(Rol), quitarRol(Rol), tieneRol(Rol).
  • Relaciones: agrega/quita Rol; referenciado por Trabajo (autor), Pago, InscripcionCongreso, Evaluacion, AsignacionEvaluacion, Notificacion, Certificado.

Congreso

  • Atributos: nombre, edicion, etapas (Map EtapaProceso → RangoFechas).
  • Métodos: constructor, definirEtapa(EtapaProceso, LocalDate, LocalDate), estaEtapaHabilitada(EtapaProceso, LocalDate).
  • Relaciones: usa EtapaProceso y RangoFechas; una instancia es contenida por SistemaGestionCongreso.

RangoFechas

  • Atributos: desde, hasta (LocalDate).
  • Métodos: constructor, contiene(LocalDate).
  • Relaciones: valor embebido en el mapa de Congreso.

Trabajo

  • Atributos: id, autorPrincipal (Usuario), coautores (List String), titulo, resumen, ejeTematico, tipo (TipoTrabajo), estado (EstadoTrabajo), documentoUrl, fechaCreacion, evaluaciones (List Evaluacion).
  • Métodos: constructor; getters (getId, getAutorPrincipal, getTitulo, getEjeTematico, getTipo, getEstado, getFechaCreacion, getEvaluaciones, getCoautores), agregarCoautor(String), enviar(), pasarAEvaluacion(), registrarEvaluacion(Evaluacion), aplicarDecisionFinal(RecomendacionEvaluacion), notificarDecision().
  • Relaciones: → Usuario (1); contiene muchas Evaluacion; usa TipoTrabajo, EstadoTrabajo, RecomendacionEvaluacion; enlazado en AsignacionEvaluacion y listas del sistema.

Evaluacion

  • Atributos: id, evaluador (Usuario), recomendacion (RecomendacionEvaluacion), comentario, fecha.
  • Métodos: constructor; getters (getId, getEvaluador, getRecomendacion, getComentario, getFecha).
  • Relaciones: → Usuario (evaluador); pertenece a Trabajo vía su lista.

AsignacionEvaluacion

  • Atributos: id, trabajo (Trabajo), evaluador (Usuario), aceptada, fechaRespuesta.
  • Métodos: constructor; getters (getId, getTrabajo, getEvaluador, isAceptada, getFechaRespuesta), aceptar(), rechazar().
  • Relaciones: → Trabajo (1), → Usuario (1, evaluador).

InscripcionCongreso

  • Atributos: id, participante (Usuario), categoria, estado (EstadoInscripcion), fechaSolicitud, motivoRechazo, pago (Pago, opcional).
  • Métodos: constructor; getters (getId, getEstado), asociarPago(Pago), confirmar(), rechazar(String).
  • Relaciones: → Usuario; opcionalmente → Pago; confirmar() invoca participante.agregarRol(PARTICIPANTE).

Pago

  • Atributos: id, participante (Usuario), monto, metodo (MetodoPago), requiereFactura, comprobanteUrl, estado (EstadoPago), motivoRechazo, qrAcreditacion, fechaRegistro.
  • Métodos: constructor; getters (getId, getEstado, getQrAcreditacion), aprobar(String qr), rechazar(String), reintentar().
  • Relaciones: → Usuario; asociado desde InscripcionCongreso.

Actividad

  • Atributos: id, titulo, tipo, aula, inicio, fin.
  • Métodos: constructor; getters (getId, getAula, getInicio, getFin), reprogramar(...), seSuperponeCon(Actividad).
  • Relaciones: compuesta en CronogramaPersonal; comparada con otras Actividad en SistemaGestionCongreso (conflicto aula/horario).

CronogramaPersonal

  • Atributos: actividades (List Actividad).
  • Métodos: constructor, getActividades(), agregarActividad(Actividad), quitarActividad(Actividad).
  • Relaciones: agrega muchas Actividad (valida solapamiento).

Circular

  • Atributos: id, titulo, contenido, publicada, fechaPublicacion.
  • Métodos: constructor, publicar(), despublicar().
  • Relaciones: registrada en SistemaGestionCongreso (no referencia Usuario en el código actual).

Anuncio

  • Atributos: id, titulo, mensaje, fechaCreacion, activo.
  • Métodos: constructor, desactivar().
  • Relaciones: registrado en SistemaGestionCongreso.

Notificacion

  • Atributos: id, destinatario (Usuario), asunto, mensaje, canal (CanalNotificacion), fechaCreacion, leida.
  • Métodos: constructor, marcarLeida().
  • Relaciones: → Usuario; usa CanalNotificacion.

EnvioEmail

  • Atributos: id, destinatario (String email), asunto, cuerpo, fechaEnvio, enviado, error.
  • Métodos: constructor, marcarEnviado(), marcarError(String).
  • Relaciones: no enlaza Usuario por objeto; solo email como texto.

Certificado

  • Atributos: id, destinatario (Usuario), rolCertificado (Rol), archivoUrl, fechaEmision.
  • Métodos: constructor (sin otros métodos públicos en el archivo).
  • Relaciones: → Usuario, Rol.

PlantillaEmail

  • Atributos: id, nombre, asunto, cuerpo.
  • Métodos: constructor, renderizar(String variableTitulo, String variableEstado).
  • Relaciones: independiente en el código actual (no asociada a otras clases por campo).

SistemaGestionCongreso

  • Atributos: congreso (Congreso), listas: usuarios, trabajos, asignaciones, actividades, circulares, anuncios, pagos, inscripciones, notificaciones, emails.
  • Métodos: constructor, registrarUsuario(Usuario), postularTrabajo(Trabajo), asignarTrabajoAEvaluador(Trabajo, Usuario), registrarPago(Pago), registrarInscripcion(InscripcionCongreso), registrarCircular(Circular), registrarAnuncio(Anuncio), enviarNotificacionInterna(Usuario, String, String), registrarEnvioEmail(String, String, String), crearActividad(Actividad).
  • Relaciones: aglutina Congreso y colecciones de las entidades anteriores; orquesta reglas (etapas, límites de trabajos, roles, conflictos de agenda).

Resumen de relaciones entre clases

  • Usuario — composición con Rol (conjunto de roles).
  • Congreso — mapa EtapaProceso → RangoFechas.
  • Trabajo — referencia Usuario (autor); lista de Evaluacion; enums TipoTrabajo, EstadoTrabajo.
  • Evaluacion — referencia Usuario (evaluador); RecomendacionEvaluacion; contenida en Trabajo.
  • AsignacionEvaluacion — Trabajo + Usuario (evaluador).
  • InscripcionCongreso — Usuario + opcional Pago; EstadoInscripcion.
  • Pago — Usuario; MetodoPago; EstadoPago.
  • CronogramaPersonal — lista de Actividad.
  • Actividad — sin referencia a Usuario en esta clase; conflictos vía SistemaGestionCongreso y CronogramaPersonal.
  • Notificacion — Usuario + CanalNotificacion.
  • Certificado — Usuario + Rol.
  • SistemaGestionCongreso — contiene Congreso y gestiona colecciones de: Usuario, Trabajo, AsignacionEvaluacion, Actividad, Circular, Anuncio, Pago, InscripcionCongreso, Notificacion, EnvioEmail.

Nota: CronogramaPersonal no está referenciado desde SistemaGestionCongreso en el código actual; puede modelarse como uso por otro contexto o ampliarse en una iteración futura.
